## 4. Force-update investigation (user complaints)

### Symptom

After publishing **Android update notice** in Admin, many users saw:

- **"Could not load feed."**
- **"Response not successful: Received status code 500"**

—not the intended blocking **Update required** modal.

### Root cause

Production API test confirmed:

- Outdated clients (`X-Android-Version-Code: 10`) → **HTTP 500** with GraphQL body containing `ANDROID_UPDATE_REQUIRED`
- Current clients (`X-Android-Version-Code: 15`) → **HTTP 200**, feed loads normally
- Server `minAndroidVersionCode` at time of test: **14**

Apollo Client treated HTTP 500 as `networkError`, but the app only read `graphQLErrors` for `ANDROID_UPDATE_REQUIRED`. The update modal never triggered; the feed showed a raw 500 error instead.

### Frontend fixes (this session — not in `1.0.14-15` build)

| File | Change |
|------|--------|
| `mobile/lib/forceUpdateState.ts` | Parse `ANDROID_UPDATE_REQUIRED` from HTTP 500 response body (`networkError.result.errors`) |
| `mobile/lib/apolloClient.ts` | Error link now handles both `graphQLErrors` and `networkError` |
| `mobile/app/tabs/index.tsx` | Hide feed error when `needsUpdate`; use `getApolloErrorMessage()` instead of raw `error.message` |

### Backend fix still recommended

`android-version-enforcement.plugin.js` should return **HTTP 200** with GraphQL errors (not HTTP 500) for `ANDROID_UPDATE_REQUIRED`, so **already-installed old APKs** also show the update modal without needing a new app build.

### Force-update behaviour (reminder)

| Condition | Popup? |
|-----------|--------|
| Play release only, Admin min = 0 | ❌ No one |
| User on v14, Admin min = 14 | ❌ No (`14 < 14` is false) |
| User on v14, Admin min = 15 | ✅ Yes (if client/backend handle error correctly) |
| User on v15, Admin min = 15 | ❌ No — up to date |

Popup is **not automatic** on Play upload. Admin must publish **Android update notice** with a min `versionCode` after rollout.
