## DONE: Lineup Timing Fix

**File**: `CTrend/src/fixtures/fixtures.service.ts`

**Problem**: Lineups were only appearing after kickoff. The football API publishes lineups ~60 min before kickoff but the backend never polled for them — the cron only hit `/fixtures/live` which returns IN_PLAY matches only.

**Change**: Added `syncPreMatchLineups()` method. Called from `syncLiveIfActive()` as `void this.syncPreMatchLineups()` before `syncLiveScores()`.

**What it does**:
- Every cron tick (30s), if any fixture is within 90 min of kickoff, queries DB for SCHEDULED/TIMED fixtures kicking off within 70 min with no lineups yet
- Hits `/fixtures/lineups?fixture={id}` for each (one API call, no events/stats waste)
- Throttled: max once per 3 min per fixture via `lastDetailSync` map
- If lineups returned: saves to DB → sets `lineupAvailable: true` on post → push notification to all users
- Once lineups saved, fixture drops out of the query automatically

**Expected result**: Users get "⚽ Lineups Confirmed" push ~60 min before kickoff instead of after.

**Watch in logs after deploy**:
```
Pre-match lineup check for fixture {id} (..., kickoff in X min)
Pre-match lineups saved for fixture {id}: 2 team(s)
```

**If broken**:
- No log lines → `hasActiveWindow()` not triggering (fixture kickoff must be ≤90 min away in DB)
- Notification spam → `lastDetailSync` throttle check
- Wrong home/away lineup → `homeTeamExternalId` null on fixture, name fallback used
- **Rollback**: remove `void this.syncPreMatchLineups();` from `syncLiveIfActive()` — one line

## DONE: "Match starts soon" appearing in real-time fix

**File**: `CTrend_frontend/src/components/FeedPostCard.tsx` (lines 1723–1725)

**Problem**: `showMatchStartsSoon` and `showMatchCalculating` checked `post.isVotingOpen === false` (raw server prop). This meant "Match starts soon · voting is closed" and "Revealing winner…" banners never appeared until a subscription fired or the user reloaded — even though the client-side countdown already hit zero.

**Change**: Changed both to use `isVotingClosed` instead:
```tsx
// Before
const showMatchStartsSoon = isMatchPost && isMatchNotStarted && post.isVotingOpen === false && !showCampaignWinner;
const showMatchCalculating = isMatchPost && isMatchFinished && post.isVotingOpen === false && !showCampaignWinner;

// After
const showMatchStartsSoon = isMatchPost && isMatchNotStarted && isVotingClosed && !showCampaignWinner;
const showMatchCalculating = isMatchPost && isMatchFinished && isVotingClosed && !showCampaignWinner;
```

`isVotingClosed = activeIsVotingOpen === false || votingEndedByTime` — triggers as soon as `nowMs` (1s ticker) passes `votingEndsAt` without requiring a subscription.

**Expected**: "Match starts soon · voting is closed" appears the instant the countdown hits zero. No subscription or reload needed for this banner.

## DIAGNOSIS: Real-time vote count updates not working

**Root cause candidates** (confirm by checking browser DevTools → Network → WS tab):

1. **`VITE_GRAPHQL_WS` not set in production** — This is the most likely cause. Without it, `wsLink = null` and all subscriptions silently fall back to HTTP which can't handle subscriptions. Result: vote counts never update until reload.
   - Check: Look for an active WebSocket connection in DevTools Network → WS
   - Fix: Set `VITE_GRAPHQL_WS=wss://your-backend-domain/graphql` in your production env vars (Render/Vercel/DigitalOcean dashboard)

2. **WS connected but subscription events not received** — If the WS connects but no frames arrive after voting, the issue is server-side pubsub not firing. The backend's `votes.service.ts` publishes `POST_VOTE_UPDATED` correctly — check backend logs for errors.

**How subscriptions work (for context)**:
- Each `FeedPostCard` subscribes individually to `POST_VOTE_UPDATED(postId)`
- When a vote happens → backend publishes event → subscription resolver calls `toGql(post, userId)` per subscriber → Apollo writes to normalized cache → `FEED_POSTS` query re-renders → card updates
- The `onData` handler ALSO sets `optimisticVote` for immediate UI update
- Effect at line 737 clears `optimisticVote` once `post` props update from cache

**WS config in code**:
- Local: `VITE_GRAPHQL_WS` in `.env.local` = `ws://localhost:4000/graphql` ✓
- Production: must be set manually in deployment env vars
